# Evidence review evaluation

`cases.json` 是隔离的诊断短句，非作者作品或生成章节。每例包含当前输入、历史记录、审查类型、预期行为、禁止行为和确定性替身模式。测试运行时才在系统临时目录生成 Markdown Harness，退出后清理。正式 manuscript、book、inbox 不参与测试。

## 三种证据必须分开报告

1. `pnpm eval:review`：真实 Go HTTP API → OpenAI-compatible HTTP 替身 → JSON/引用校验 → 状态持久化。覆盖 A–H、授权、幂等、UTF-16、反馈 CAS、过期、取消和 OpenAPI 响应；已纳入 `pnpm test`。它证明工程不变量，不能证明模型识别矛盾的能力。B/D/E 的空输出是预设，不是模型判断。
2. `pnpm eval:review:live`：**会发送这些合成夹具给本地配置的真实模型**，需要显式运行此命令。先设置服务端 LLM 环境变量；不要写密钥到仓库。输出模型、运行状态、有效候选数量；不能自动判定语义质量。2026-10-16 按用户决定未执行。
3. 真实作者反馈：有用、误报、有意为之、忽略保存在 Review Run 应用状态。需积累使用样本后再报告比例；当前没有质量数据。不能把“有意为之”直接归为模型错误。

## 人工评分表（每例）

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 证据覆盖 | 假来源/假引文 | 来源真实但不支持推断 | 至少两处相关原文，足以讨论 |
| 判断边界 | 确定作者写错 | 有不确定词但忽略角色视角 | 区分台词/叙述/认知并保留其他解释 |
| 作者价值 | 无法行动或强制改稿 | 可读但问题宽泛 | 具体可回答的问题，作者可拒绝 |
| 信息不足 | 补造事实 | 提示不确定但无有效证据 | 空结果或不作为已核验发现展示 |

记录 provider/model、日期、配置、案例 ID、输出、评分与评审者。建议真实模型同一案例重复至少三次观察波动；先人工审阅 B（谎话）和 D（信息不足）。没有人工评分时，结果仅标记 `manual scoring required`。

## 工程硬门槛

非法来源接受数、未授权正文修改、未确认设定自动写入、未保存版本误当最新版、主动打断输入均要求为 0；所有展示为核验通过的引文必须精确命中授权快照。失败/超时/非法结构不得回退 Demo 或声称已完成。语义相关性、冲突真实性仍由模型和作者判断，字面引用校验不能证明它们。
