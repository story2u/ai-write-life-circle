# Writer Agent VNext · UI/UX 设计规范与 Codex Handoff

- Document ID: `DES-VNEXT`
- 状态：**设计权威（UI/UX）**。取代 V0.3 原型的布局与信息架构；V0.4 的 API 契约、领域模型中未被本文修改的部分继续有效。
- 原型源码：`src/`（Figma Make）。Codex 通过 Figma MCP 读取；Figma Make 负责最终 UI/UX，Codex 负责工程实现。
- 一句话：**一张会记得整本书的安静稿纸。作者的注意力属于作品，不属于 Agent。**

> 所有 Agent 输出（注记、冲突检测、思考中的复述 / 挑战 / 研究、定稿变更影响分析）在原型中均为本地脚本模拟，并在界面上标记“原型 · 模拟”。不得据此认为后端或 Agent 能力已实现。

## 1. 信息架构

一级导航只有三项（顶栏居中）：

| 一级 | 目的 | 包含 |
|---|---|---|
| **写作** | 主工作空间，默认进入 | 稿纸（TipTap）、左抽屉「目录 / 本章相关」、右抽屉「注记 / 思考」、续写开场、随手记、保存与版本状态、故事冲突对照 |
| **书** | 作品的长期记忆 | 本章相关（默认）、人物、世界与规则、时间线、剧情结构、伏笔、创作笔记、变更历史、条目详情、定稿变更 |
| **思考** | 作者主动发起的深入讨论 | 思考会话列表 + 完整会话视图。**与写作页右侧「思考」抽屉是同一会话、同一数据** |

辅助面板只有 **注记 / 思考** 两项。原来的「审查 / 对话 / 推演 / 决策」四个平级 Tab 已取消：

| V0.3 | VNext |
|---|---|
| 审查 | → 页边注记（锚定段落） + 故事冲突对照 |
| 对话 | → 合并入「思考」（理解 → 挑战 → 启发 → 结论） |
| 推演（Tab + 独立推演工作台） | → 合并入「思考」；独立工作台删除 |
| 决策 | → 「书 · 变更历史」和条目详情内的变更历史 |
| 提案 | → 拆成两个概念：**创作笔记**（轻）与 **定稿变更**（严谨） |
| 知识库首页 / 关系图 / 冲突中心 | → 「书」；关系图删除（在信息不足时会制造“看似准确”的假象）；冲突在正文边缘和对照页处理 |
| 设计说明 | → 移出作者导航，仅在「原型」菜单 → “设计规范与 Codex Handoff” |

界面上**不出现**技术 ID（`WORLD-001`、`P-001`、Harness 路径）。使用自然语言：“首次出现：第 3 章”“最后确认：第 12 章”。内部 ID 仍保留在数据模型中。

## 3. 组件清单与交互规范

所有基础组件位于 `src/components/ui.tsx`：`Btn`（primary / quiet / outline / danger / link；sm / md）、`IconBtn`、`Row`、`Heading`、`TextArea`、`TextInput`、`Seg`、`Quote`、`Dot`、`Proto`、`Kbd`、`Dialog`、`Toasts`、`Skeleton`、`Icon`。功能组件不直接写原生控件。

| 组件 | 关键行为 |
|---|---|
| `ManuscriptEditor` | 正文无卡片、无边框。页边标记是段落右侧外的 6px 细点（ProseMirror widget 装饰）；点击后才给段落铺底色、给引文加下划线。标记与正文分离，**不写入文档**。支持 `editable=false`（只读保护 / 待恢复）。`flash` 用于“返回正文原位”时的段落闪烁和滚动定位。 |
| `Resume` | 只在会话开始时出现，位于章节标题之上，不是弹窗。展示上次章节、末尾最多三段**原文**、作者自己写的“下次要写”、最多三条本章相关待决事项。动作：继续写 / 先想一想 / 直接进入正文 / ×。没有正文时不显示；作品没有章节时显示真正的空状态，不生成示例正文。 |
| `ChapterDrawer` | 「目录」：卷可折叠，只展开当前卷；可搜索；100 章规模可用。「本章相关」：见 §6。 |
| `MarginPanel` | 按段落顺序。每条注记分三层：**事实**（引文 + 来源 + 查看原文）、**推断**（紫色虚线，明确标注“AI 的理解，未经确认”）、**问题**（留给作者的问题，不给改写段落）。动作：进入冲突对照（仅冲突类）/ 记为创作笔记 / 就此思考 / 暂时忽略。状态：`fresh` / `stale`（原文已改动）/ `source-missing`（来源未建档）。不显示置信度百分比。可在本次写作中关闭所有页边标记。 |
| `ThinkingSession` | 同一组件用于抽屉（窄）和完整空间（`wide`）。进程条：理解 · 挑战 · 启发 · 结论。AI 先复述（事实性复述为实线，推断为虚线 + “推断”），作者可“不对，我来纠正”；挑战为带标签的条目和问题；研究只分析**表达机制**，每条标明出处核验状态（已核对 / 未核验 · 请勿直接引用）。结论由作者自己写，保存为**创作笔记**。 |
| `QuickNote` | ⌘; 或「随手记」或选区「记一笔」。底部浮出一行，Enter 保存，Esc 关闭，焦点回到正文。可标为“下次要写”（全书只保留一条）。不需审批，不成为设定。 |
| `StoryConflictView` | 两段原文并排（窄屏堆叠）+ 已确认事实 + AI 分析（推断）+ 可能读法 + 留给作者的问题。四个作者动作，每个都写明后果：①人物成长 / 认知变化 → 记笔记，两处正文都不改；②我要修改正文 → 回到编辑器对应段落，由作者改；③我要修改设定 → 起草定稿变更；④有意为之 → 不再提醒。顶部始终有“回到正文原位置”。 |
| `SaveConflictDialog` | 仅用于 **409 版本冲突**，与故事冲突在文案、颜色（`danger` 而非 `conflict`）、位置上完全分开。说明本地草稿已完整保留；动作：保留本地草稿，稍后处理 / 导出本地草稿 / 查看服务器版本（并排） / 使用服务器版本…（二次确认 + 勾选“我已导出或确认不需要”）/ 版本对比（规划中，禁用）。 |
| `Banner` / `SaveStatus` | 数据安全信息。保存失败、409、待恢复始终可见，**不随打字淡出、不在专注模式中隐藏**，并用图标 + 文字表达，不只靠颜色。 |
| `BookView` | 左侧分区，右侧单栏阅读宽度。条目详情：自然语言字段、出现章节（可跳转）、关联、来源引文、变更历史、就此思考。修改已确认知识只能经由“笔记 → 定稿变更”。 |
| `CanonChangePage` | 正式文档形态（与笔记的手记形态刻意不同）：现有内容（删除线）与变更内容并排、依据引文、涉及章节、可能影响（AI 推断）、确认说明。动作：确认变更 / 暂缓 / 放弃。原型中确认只模拟更新条目，并标“模拟写入”。 |

## 4. 状态说明

**保存（`SaveState`）**：`loading` · `saved`（“已保存 · 第 N 版 · 时间”）· `dirty` · `saving` · `failed`（保留在本机，可重试、可导出）· `recovery`（发现较新的本地草稿；编辑暂停，需选择恢复 / 导出 / 丢弃）· `conflict`（409；自动保存暂停）· `readonly`（Markdown 含编辑器无法无损保留的结构；导出原文）。
优先级：`loading > readonly > recovery > conflict > failed/saving/dirty/saved`。

**章节**：加载中（骨架）· 空章节（“从这里开始写。”占位）· 有正文 · 长篇演示占位（无正文，明确说明）· 作品没有章节（空状态 +「新建第一章」）。

**注记**：`fresh` · `stale` · `source-missing` · 已忽略（本章内可恢复）· 已处理（随故事冲突的判断消失；选择“修改正文”的，在引文从正文中消失后自动消失）。

**创作笔记**：进行中 · 已归档 · 已提出定稿变更（显示变更状态）。

**定稿变更**：`draft` → `confirmed` | `deferred` | `abandoned`；`deferred / abandoned` 可“重新考虑”回到 `draft`。

**故事冲突**：未判断 → `growth` | `edit-text` | `edit-canon` | `intentional`。

**原型控制**（顶栏「原型」，不属于作者界面）：下一次保存失败 · 下一次 409 · 只读 · 慢速加载 · 长篇规模（100 章、30 个演示人物、24 条演示伏笔）· 新作品无章节 · 模拟待恢复草稿 · 再次显示续写开场 · 设计规范 · 重置。

## 5. Design Tokens（`src/index.css`）

保留 V0.3 的 token 名（`bg / surface / surface-2 / line / ink / ink-2 / ink-3 / accent / ai / warn / danger / ok`），新增：

| Token | 用途 |
|---|---|
| `--paper`（`bg-page`） | 稿纸。画布 `--bg`（`bg-paper`）用于抽屉，用背景层次而不是边框区分区域 |
| `--line-soft` | 极弱分隔 |
| `--ink-4` | 仅装饰（细点、引文竖线），**不用于文字** |
| `--conflict(-soft)` | 故事冲突。暖色，与 `--danger` 分开 |
| `--scrim` | 抽屉 / 对话框遮罩 |

语义规则：`danger` 只用于数据安全（保存失败、409、丢弃确认）；`conflict` 只用于故事冲突；`ai` 只用于 AI 推断和伏笔提示；`accent` 用于焦点和链接。

字体：UI 用 `--font-ui`（Noto Sans SC → PingFang SC → 微软雅黑），正文和引文用 `--font-prose`（Noto Serif SC → Songti SC → STSong → SimSun）。
字号：`micro 11 / ui-sm 12 / ui 13 / ui-lg 15 / read 16 / title 26 / display 32`；正文 `18px / 1.9`，首行缩进 2em，段距 0.9em。
宽度：`--container-page 44rem`（减去左右内边距后约 33 个汉字）· `--container-nav 17.5rem` · `--container-drawer 22.5rem`。
圆角：控件 `rounded-md`（6px），浮层 / 对话框 `rounded-xl`。阴影 `--shadow` 只用于浮层与窄屏抽屉。
焦点：`:focus-visible` 2px `--accent` 外框。交互：hover 用 `surface-2` 填充，不加边框。
动效：抽屉 200ms 滑入，浮层 220ms 上浮；打字时界面外围（`.chrome`）渐隐到 8% 透明度，鼠标移动后恢复；遵循 `prefers-reduced-motion`。
深色：暖调低眩光，不用纯黑和纯白；降低 AI / 冲突色的饱和度，保证对比度。

## 6. 本章相关（“写这一章时需要记住什么”）

`src/vnext/relevance.ts`。分四组：人物、当前生效的规则与地点、相关的历史事实、到了回收时机的伏笔。**每组最多 5 条**，超出部分折叠并显示数量。每条必须带依据（“本章正文提到‘沈砚’”“你定的回收时机：第 12–15 章”）。伏笔只有在作者自己定的回收窗口内才出现，以避免提醒疲劳。没有依据时显示空状态，不做推测性推荐。

## 7. 关键用户流程（验收）

1. **开始写作**：打开 → 续写开场（末尾三段原文 + 下次要写 + ≤3 待决）→ 继续写（光标到正文末尾）→ 自动保存（1.5s 空闲）→ “已保存 · 第 N 版”。
2. **记录想法**：写作中按 ⌘; → 写一行 → Enter → toast（“它只是笔记，不会变成设定”）→ 焦点回到正文。稍后在「书 · 创作笔记」找回。
3. **查看注记**：点页边细点 → 右抽屉展开对应注记，段落铺底色 → 事实 / 推断 / 问题 → 「查看原文」可跨章节跳转，顶部出现“回到第 12 章第 2 段” → 回到原位置并闪烁定位。
4. **深入思考**：选中文字 → 「思考这段」→ AI 复述 → “不对，我来纠正” → 重新复述 → “挑战它” → “看看别的作品” → 写下结论 → 保存为笔记。抽屉可展开为完整「思考」，是同一会话。
5. **定稿变更**：书 · 创作笔记 → “这是一个设定变更…” → 现有 vs 变更、依据、涉及章节、影响 → 确认 / 暂缓 / 放弃 → 变更历史记一笔（原型标“模拟写入”）。
6. **保存冲突**：原型菜单开启“下一次 409” → 编辑 → 对话框说明本地草稿已保留 → 查看服务器版本 / 导出 → 保留本地稍后处理（横幅 + 顶栏状态持续可见）或二次确认后使用服务器版本。
7. **长篇创作**：原型菜单开启“长篇规模” → 目录按卷折叠、可搜索；书中 60+ 条知识可按名字查找；伏笔按“到了时机 / 已过时机 / 未到 / 已回收”分组；本章相关仍限制在每组 5 条。

## 8. 前后端与 Agent 需求矩阵

### 8.1 现有 API 已可支持（Sprint 1–2）
- Workspace 状态与偏好（主题、抽屉开合、专注）→ `getWorkspace` / 偏好同步
- 章节列表、章节加载（Markdown）→ `listChapters` / `getChapter`
- Markdown 编辑、自动 / 手动保存、版本号 → `saveChapterRevision`（`baseRevisionId` + `Idempotency-Key`）
- 409 冲突、服务器版本读取 → 现有 409 响应 + 重新获取章节
- 本地恢复草稿、导出 → 前端已实现（per-project / per-chapter）
- 只读保护：需要后端或解析层返回“不可无损编辑”的标记（若尚无字段，**需新增**一个布尔字段）

### 8.2 需要新增 API / 数据模型（候选，**未实现**）
- `Note`：创作笔记（`text, origin, chapterId?, para?, quote?, nextUp, archived, sessionId?, canonChangeId?`）
- `Margin`：页边注记的存储、段落锚点（段落序号 + 引文 + 章节修订 ID），以及 `fresh/stale/source-missing` 的计算
- 本章相关聚合接口：返回每组 ≤5 条，每条带 `why`
- `Entry`：人物 / 规则 / 地点 / 事实 / 伏笔 / 剧情，自然语言字段、出现章节、关联、来源、`thread.window`
- `Change`：知识变更历史（取代 V0.4 的 Decision 列表视图）
- `CanonChange`：`draft → confirmed | deferred | abandoned`；确认后写入正式档案（Harness / Git）需作者身份
- `StoryConflict`：证据对 + 作者判断（`resolution`）
- `Session`：思考会话（块序列）
- 续写开场：上次编辑章节 + 时间（可由 Workspace 偏好扩展）

### 8.3 需要真实 Agent Runtime（**未实现**）
- 连续性审查（生成 `Margin` 与 `StoryConflict`）
- 人物事实推理、人物知识边界
- 时间线矛盾检测
- 思考中的复述、纠正后的重新理解、挑战
- 有出处的表达研究与引文核验（未核验必须标出）
- 定稿变更的影响分析（标为 AI 推断）

Agent 永远不写 `manuscript/`，不直接改已确认设定；所有正式变更经由 `CanonChange` 的作者确认。

## 9. 与 V0.3 / V0.4 原型的差异摘要

- **保留**：TipTap 编辑、Markdown 原文保护、自动 / 手动保存与状态、409 保护、本地恢复与导出、版本概念、浅色 / 深色、专注模式、章节导航、事实 / 推断分色、证据引用、“演示数据”标识。
- **合并**：审查 → 注记；对话 + 推演 + 推演工作台 → 思考；决策 → 变更历史；知识库 + 冲突中心 → 书。
- **移除**：右侧四 Tab、待处理数字徽标、常驻 Agent 面板、关系图、作者界面中的技术 ID 与 Harness 路径、设计说明入口、每条对话一键生成提案。
- **新增**：续写开场、页边细点、随手记与“下次要写”、本章相关、故事冲突对照页、定稿变更页、思考的四阶段与纠正、原型控制菜单、打字时界面渐隐。
